# 성분 라벨 점검과 다음 수집 기준 — 2026-09-20

## 결정

현재 자료로 대회 전체 Score를 계산하지 않는다. 기존 파일 진위 판별 실험은 그 범위에서 유지하지만, 그 결과를 Voice EER·Music EER 또는 성분 존재 AUC로 바꾸어 해석하지 않는다. 제출 모델 교체나 추가 가중치 탐색보다 성분 정답과 독립 원본 확보가 먼저다.

이번에 완료한 것은 **기존 라벨의 근거 점검, 후속 수집 후보 선정, 재사용 원본 제외 목록 저장**이다. 새로운 오디오 다운로드·청취·GPU 추론·제출 ZIP 생성은 아직 하지 않았다. 새 Colab 실행 파일이 준비됐다고 안내해서는 안 된다.

## 확인 근거

- [AI-OpenBMAT 논문 2.2절](https://arxiv.org/html/2602.06823v1): 비음악 소스에는 대부분 말소리가 있지만 박수·환경음도 포함된다. 따라서 메타데이터의 `speech`만으로 Voice Presence=1을 확정할 수 없다. 음악 소스의 생성 여부도 DACON의 악기 성분 정의와 일치하는지 별도 확인해야 한다.
- [MUSAN 공식 배포 페이지](https://www.openslr.org/17/), 로컬 `data/raw/musan-metadata-20260912/music_inventory.csv`와 출처별 ANNOTATIONS/LICENSE: 보컬 표시는 곡 전체에 대한 주석이다. Y인 곡의 임의 8초 구간에 반드시 보컬이 있다는 뜻은 아니다. N도 독립적인 구간 청취 검증과 같지 않다.
- 기존 manifest의 파일 진위 정답을 보존하고, 이번 감사 파일에서는 검토되지 않은 성분 정답을 `null`로 남겼다. 기존 학습·예측 파일은 수정하지 않았다.

|---|---:|---|---|---|
| music-pilot의 MUSAN 원본 주석 | 보컬 Y 4, N 6 | [감사 JSON](../data/research/component-labels-20260920/audit.json) | 2026 | 곡 단위, 잘라낸 구간의 정답 아님 |
| file-probe의 MUSAN 원본 주석 | 보컬 Y 29, N 14 | 같은 감사 JSON | 2026 | 파일 행 수이며 독립 아티스트 수 아님 |
| 후속 수집 조건에 맞는 트랙 | 110 | 같은 감사 JSON 및 저장된 LICENSE | 2026 | N, 기존 두 음악 manifest의 아티스트 문자열 제외, 명시적 BY/BY-SA 3.0/4.0 |
| 우선 수집 후보 | 12 | 같은 감사 JSON | 2026 | 아티스트 문자열당 한 곡, 해시 순서로 선정 |

후보 수집 조건을 전체 장르에 적용했다. 기존 FMA 범위만으로는 위 조건에 맞는 새 후보가 없었다. 라이선스 블록에서 식별자와 명시된 CC 조건을 함께 읽으며 ND·불명확한 조건은 선택하지 않았다. 후보의 재배포 시에는 해당 출처의 표시·동일조건 의무를 보존해야 한다.

## 다음 실행에 적용할 기준

1. 감사 JSON의 `fresh_instrumental_candidates` 순서로 원본을 수집한다. 출처 라이선스, 원본 SHA-256, 표본화율, 실제 길이를 함께 보관한다. 현재 `audio_downloaded=false`다.
2. 곡/아티스트 문자열 외에 별칭·동일 녹음 중복을 확인한다. 현재 선정은 기존 두 음악 manifest와의 문자열 중복 제외만 보장한다. 모든 과거 데이터나 사전학습 데이터와의 독립성을 보장하지 않는다.
3. 원본을 나눈 뒤 구간을 추출한다. 같은 곡의 다른 구간을 학습/검증에 나누지 않는다. 보컬 없음 주석과 실제 사용할 구간의 성분을 확인한다.
4. 음성 자료는 저장된 utterance뿐 아니라 화자도 확인한다. 기존 LJSpeech/WaveFake 자료는 Linda Johnson 화자를 공유하므로 새 문장만 얻어도 화자 독립 검증셋이 되지 않는다.
5. 실제 성분 정답이 확보된 항목만 평가한다. REAL 음악만 있는 집단에서 Music EER을 만들지 않고, 단일 클래스인 항목은 계산 불가로 기록한다. 전체 5개 지표가 유효하기 전에는 대회 Score로 합산하지 않는다.
6. 모델 비교 전에 사용할 모델·집계·채택 기준을 고정한다. 점수를 본 뒤 좋은 원본이나 생성기만 골라내지 않는다.

AI-OpenBMAT의 기존 pair ID, 음악/비음악 소스 ID, 방송 reference ID와 기존 음악·음성 SHA-256을 `exclusions`에 저장했다. 이 목록은 명시한 manifest 범위의 제외 목록이며 전체 프로젝트 원본의 완전한 목록은 아니다.

## 재현과 검증 범위

저장소에서 `python -X utf8 -B scripts/audit_component_labels.py` 실행. 표준 라이브러리만 사용한다. 주석 ID의 유일성, 기존 MUSAN 원본과 주석 연결, 후보의 트랙/아티스트 문자열 중복 배제를 assertion으로 확인한다. 라이선스 확인은 로컬에 보존한 배포본의 텍스트에 한정되며, 새 오디오의 진위·음질·성분은 미검증이다.

사용: Python/PowerShell — 로컬 manifest와 주석 대조. 웹 원문 — AI-OpenBMAT 성분 라벨의 한계와 MUSAN 공식 출처 확인.
