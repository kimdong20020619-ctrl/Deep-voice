# 생성기·길이·코덱 통제 비교 준비 — 2026-09-19

## 목적과 판단 범위

SONICS가 방송 음원에서 개선되고 기존 음악 개발 자료에서 악화된 이유를 바로 특정 생성기의 영향으로 단정하지 않는다. 이번에는 보유한 여러 생성기의 음원을 같은 길이·코덱 조건으로 처리하고 SONICS와 DF-Arena를 같은 입력에서 비교한다. 모델·임계값·융합 가중치를 학습하지 않는다.

이번 단계는 기존 개발 자료를 확장해 보는 진단이다. 새로운 독립 검증셋을 확보한 것은 아니다. 기존 `holdout`도 과거 실험에서 이미 확인했으므로 `historical_split` 기록만 보존하고 잠금 검증셋으로 주장하지 않는다. 새 방송 음원 수집, 60초 길이의 통제 비교, 실제 음성 혼합 추가는 이번 범위에 포함하지 않았다.

## 고정한 처리 조건

1. 모든 원본은 16 kHz 모노 PCM16, 8초다. 정수 PCM을 32768로 나누어 float32로 변환한다. 이전 준비 단계의 음량 처리 결과를 보존하며 추가 파일 집단 통계는 사용하지 않는다.
2. 같은 원본의 가운데 5초(시작 1.5초)와 8초 전체를 각각 사용한다. 5초와 8초 차이에는 문맥 길이뿐 아니라 포함된 내용과 구간 집계 수 차이도 있으므로 순수 길이 효과라고 단정하지 않는다.
3. 각 길이마다 원본 및 MP3 64 kbps 재인코딩/디코딩 조건을 만든다. 디코딩 후 샘플 수가 원본과 다르면 오류로 중단한다. 동일한 디코딩 배열을 두 모델에 입력한다.
4. SONICS는 공식 alpha-5s 가중치를 고정한다. 모델 전용 구간 표준편차 정규화와 5초 창을 사용한다. 8초는 시작 0초·3초의 두 창을 평균하고, 5초는 한 창이다. 구간 확률 평균만 주 점수로 기록한다.
5. DF-Arena는 기존 코드의 direct/max 설정으로 동일 입력을 새로 추론한다. 기존 원본 점수를 MP3 점수 대신 사용하는 비교는 하지 않는다. 음악 분리·존재 탐지·선형 판별기는 실행하지 않는다.
6. 84개 × 2길이 × 2코덱 = 336조건에서 두 모델의 파일 점수를 얻는다. 각 생성기와 실제 음악 대조군을 비교한 EER/AUC를 길이·코덱별로 따로 저장한다. 대회 MUSIC EER 또는 전체 Score는 산출하지 않는다.

MUSAN 음악 원본에 보컬이 있을 수 있으므로 ‘음악 원본’을 ‘음성 성분 없음’으로 라벨링하지 않았다. 이번 비교는 원본 파일의 REAL/FAKE만 평가한다. 값이 좋다는 이유만으로 대회의 MUSIC_FAKE_PROB를 교체하지 않는다.

## 실행과 기록

- `scripts/run_generator_check.py`: 입력 제작, 동일 입력 두 모델 추론, 생성기별 요약.
- `scripts/make_generator_check.py`: 번들과 Colab 노트북 생성.
- `scripts/selftest_generator_check.py`: 입력·집계 모집단·노트북 및 번들 검사.
- 기존 모델 코드와 라이선스를 포함하고 HF 가중치는 이전과 동일한 고정 리비전 및 SHA-256으로 확인한다. 가중치 검사는 큰 파일을 메모리에 통째로 올리지 않고 스트리밍한다.
- GPU 메모리 사용을 줄이기 위해 DF-Arena 계산을 마친 뒤 해제하고 SONICS를 실행한다.
- 결과에는 336조건의 입력 해시·크롭 시작점, DF 점수, SONICS 구간 로짓, 예측 CSV, 가중치 해시 검사 기록, 소스 및 환경/실행 로그를 남긴다. MP3 실제 파형 전체와 DF의 GPU 내부 로짓은 반환하지 않으므로 결과 회수만으로 독립 GPU 재현이 완료되는 것은 아니다.
- Colab은 승인된 `timm==1.0.15`와 이전 실험에서 사용한 `demucs==4.0.1`을 준비한다. demucs는 제출 코드 import 때문에 필요하지만 분리 모델 가중치는 받지 않는다. 라이브러리 import 검사를 먼저 수행한다.
