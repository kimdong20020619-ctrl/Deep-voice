# 06. 평가 산식과 제출 규격 (전문 확정)

> 2026-09-05 대회 평가 탭 전문 확보. **이 문서의 내용은 전부 ✅ 확정이다.**

## 1. 산식

```
Score = 0.9 × ADS + 0.1 × CPS

ADS = 0.5 × (1 − File EER)
    + 0.2 × (1 − Voice EER)
    + 0.3 × (1 − Music EER)

CPS = 0.5 × Voice Presence ROC-AUC
    + 0.5 × Music Presence ROC-AUC
```

EER 계산 (대회 제공 코드):

```python
fpr, tpr, _ = roc_curve(y_true, y_score, pos_label=1, drop_intermediate=False)
fnr = 1 - tpr
idx = np.argmin(np.abs(fpr - fnr))
EER = (fpr[idx] + fnr[idx]) / 2
```

- **FAKE가 양성 클래스(1)**
- **Voice EER은 음성이 존재하는 샘플에서만** 계산 → 음악 단독 파일의 `VOICE_FAKE_PROB`은 채점 제외
- **Music EER은 음악이 존재하는 샘플에서만** 계산 → 음성 단독 파일의 `MUSIC_FAKE_PROB`은 채점 제외

## 2. 총점 기준 실효 가중치 — 자원 배분의 근거

| 예측 컬럼 | 지표 | 실효 가중치 |
|---|---|---|
| `FILE_FAKE_PROB` | EER | **0.45** |
| `MUSIC_FAKE_PROB` | EER | **0.27** |
| `VOICE_FAKE_PROB` | EER | **0.18** |
| `VOICE_PRESENT_PROB` | ROC-AUC | 0.05 |
| `MUSIC_PRESENT_PROB` | ROC-AUC | 0.05 |

### 여기서 나오는 결론 3가지

**① 음악 위조도가 음성보다 무겁다 (0.27 vs 0.18).**
딥보이스 대회라는 이름과 반대다. 그런데 베이스라인은 음성 anti-spoofing 모델(DF-Arena-1B)을
반주 스템에 그대로 적용한다 — 도메인 외 사용이다. **최대 개선 여지가 여기다.**

**② `FILE_FAKE_PROB`(0.45)이 단일 최대 항목이고, 음악 헤드에 물려 있다.**
베이스라인 융합은 `max(VP·VF, MP·MF)`이다. 음악 성분이 있는 파일에서는 File 판정이 음악 헤드를
그대로 따라간다. → **음악 헤드를 고치면 0.27과 0.45의 상당 부분이 함께 오른다.**
음악 헤드의 실효 레버리지는 0.27을 크게 넘는다.

**③ 존재 탐지(0.10)는 건드리지 않는다.**
1위 CPS 0.98932 = presence AUC 평균 0.989. PANNs zero-shot으로 이미 포화다.
개선 여지가 최대 0.001 수준이다. **투자 금지.**

> ⚠️ **정정**: 이전에 CPS를 "속도 점수일 가능성"으로 열어뒀으나, **CPS = Component Presence Score**로 확정됐다.
> **추론 속도는 점수에 전혀 반영되지 않는다.** 60분은 점수 항목이 아니라 통과/실패 조건이다.
> → 속도 최적화는 "60분 안에 들어가는 선까지만" 하고, 남는 여유를 **정확도에 재투자**한다.
>   시간이 남는다면 더 큰 모델·앙상블·TTA를 쓰는 것이 이득이다.

## 3. EER의 성질 — 설계에 영향을 준다

- EER은 ROC 기반이므로 **순위만 보존되면 값이 같다.** 단조 변환·캘리브레이션은 점수에 영향 없다.
  → 확률 캘리브레이션에 시간을 쓰지 않는다.
- 다만 EER은 **단일 동작점**이라 AUC보다 점수 분포 모양에 민감하다. REAL/FAKE가 양극으로
  갈라지는 편이 유리하다. 애매한 중간값이 많으면 EER이 나빠진다.
- `FILE_FAKE = max(VP·VF, MP·MF)`에서 존재 확률을 곱하는 것은 **순위를 왜곡한다.**
  (명백히 FAKE인 음악인데 MP=0.6이면 0.6·MF로 눌린다)
  → 대안 비교 필요: 하드 게이팅 후 `max(VF, MF)`, noisy-or `1−(1−VF)(1−MF)`, 학습 융합.
  **0.45짜리 항목이므로 융합 방식 실험은 비용 대비 효과가 가장 크다.**

## 4. 리더보드 구조

- **Public Score = 전체 테스트 데이터 100%**
- **Private Score = 대회 종료 시점의 Public Score**

→ **Public/Private 분할이 없다.** 리더보드 과적합 위험이 없고 점수를 그대로 신뢰할 수 있다.
제약은 오직 **일 3회 제출**이다.

1위 ADS 0.82323을 세 EER이 같다고 가정해 역산하면 평균 EER ≈ **17.7%**.
아직 아무도 이 문제를 풀지 못했다는 뜻이다.

## 5. 2차 평가 — 모델 성능 점수 환산식

```
모델 성능 30점 = 30 × ( 본인 Public / 진출팀 중 최고 Public )^N       (N은 1~5, 비공개)
```

N이 5라면 최고점 대비 95%여도 30 × 0.95^5 = **23.2점**으로 6.8점이 깎인다.
→ **리더보드 점수를 "15위만 넘기면 된다"고 볼 수 없다.** 격차가 지수로 증폭된다.
15위 진입은 필요조건이고, 그 뒤에도 점수를 계속 올려야 한다.

⬜ **미확인**: 2차 평가 항목 전체 배점표 (모델 성능 30점 외 나머지 항목과 총점).

## 6. 제출 규격 ✅

```
submit.zip
├── model/            # 가중치. 참가자 구성
├── script.py         # 자동 실행됨. 참가자 구성
└── requirements.txt  # 참가자 구성
```

평가 서버가 자동 추가:

```
├── data/                     # 읽기 전용. 쓰기·수정 불가
└── output/submission.csv     # 여기에 반드시 이 파일명으로 저장
```

- **최상위 폴더를 추가하면 구조 불일치로 설치 오류.** zip 루트에 위 3개가 바로 있어야 한다.
- 오류 2종의 비용이 다르다:
  - **설치 오류** (구조 불일치·패키지 설치 실패) → **일일 제출 횟수 차감 안 됨**
  - **제출 오류** (`script.py` 실행 중 발생하는 모든 오류) → **차감됨**
  → 구조 실수는 공짜지만 **런타임 에러는 하루 3회 중 1회를 태운다.** 로컬 검증이 그만큼 중요하다.

## 8. 반드시 지켜야 할 금지 규칙 ✅

**① 비공개 평가 데이터를 활용한 추가 학습 금지**
추론 시점의 학습·튜닝·Pseudo-Labeling 전부 금지.

**② 파일 단위 독립 예측 원칙**
- 허용: 한 파일을 세그먼트로 나눠 추론하고 그 결과를 종합
- **금지: 다른 파일의 정보·예측값·통계를 이용한 예측 또는 보정**

> ⚠️ EER이 순위 기반이라 **테스트셋 전체 분포로 점수를 정규화하는 트릭**(z-score, 순위 변환,
> 분위수 매핑)이 매우 유혹적인데 **명시적으로 금지**돼 있다. 실격 사유다. 절대 쓰지 않는다.
> 세그먼트 집계는 한 파일 내부의 일이므로 허용된다.

**③ 평가 데이터셋 유출 시도 → 즉시 실격**
