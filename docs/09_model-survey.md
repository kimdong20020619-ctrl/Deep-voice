# 09. 모델·지표 조사와 채택 판정

> 2026-09-05. 「공모전 주제에 가장 적합한 모델」을 객관 지표로 판정한 기록.
> 검증하지 못한 것은 ⬜ 로 표시했다. 2차 평가 「모델 개발 보고서」의 근거 자료다.

## 0. 판정 기준 — 이 대회의 제약이 곧 필터다

어떤 모델이든 아래를 전부 통과해야 채택 가능하다. 성능은 그다음이다.

| 기준 | 값 | 탈락 조건 |
|---|---|---|
| 라이선스 | 공개 + 최소 비영리 허용 | 상업 전용·비공개 |
| 오프라인 | 가중치 동봉 후 인터넷 없이 실행 | 런타임 다운로드 필수 |
| 의존성 | 평가 서버 기본 설치 목록 안에서 해결 | 새 패키지 설치 실패 시 설치 오류 |
| 용량 | 현재 4.66 GB + 여유 약 5 GB | 10 GB(해제 32 GB) 초과 |
| 속도 | 60분 / 1,200파일 | 예산 초과 = 실행 실패 |
| 입력 | 16 kHz, 4~60초, MP3·FLAC·전화채널 내성 | 압축·대역제한에 취약한 방법 |

마지막 줄이 결정적이다. 평가셋에 **MP3·FLAC 혼재와 전화채널이 명시**돼 있다.

### 판정: **DF-Arena 1B 유지** ✅

근거 셋.

1. **오픈소스 최상위가 pooled EER 15.68%다.** DF-Arena 자체 보고 EER(모델 카드)은

   ⬜ **주의**: 다수가 학습 데이터에 포함된 in-domain 수치라 낙관적이다. 직접 비교는 불가하다.
2. **가창(CTRSVDD)·환경음(EnvSDD)까지 학습**돼 있다. 음악이 섞이는 이 과제에서
   순수 음성 모델(AASIST 계열)보다 유리한 유일한 후보다.
3. **주최측이 베이스라인으로 배포한 모델**이라 라이선스·오프라인·용량이 이미 검증돼 있다.
   교체는 이 검증을 전부 다시 해야 한다.

### 참고 — 리더보드 선두의 위치 추정

DACON 1위 ADS 0.82323 을 세 EER 동일 가정으로 역산하면 **평균 EER ≈ 17.7%** 다.

→ **선두도 zero-shot 공개 SOTA 수준에 머물러 있을 가능성이 높다.** 아직 아무도 이 문제를 풀지 못했다.

### ⬜ 보류 — 앙상블

다만 연산이 2배가 되고 현재 시간 예산이 빠듯하다. **음악 헤드 정리 후 재검토.**

## 2. 생성 음악 탐지 — 실효 가중치 0.27의 공백

DF-Arena 학습 목록에 **악기·반주(instrumental) 생성 음악이 없다.**
`MUSIC_FAKE_PROB` 이 도메인 밖인 근거이며, 이 대회 최대 개선 여지다.

### 후보 평가

| 후보 | 라이선스 | 크기 | 입력 | 의존성 | 보고 성능 | 판정 |
|---|---|---|---|---|---|---|
| **SONICS SpecTTTra-γ-5s** | MIT | 17M / ~0.1GB | 16 kHz, 5초 | `pip install git+github` | F1 0.76 · 민감도 0.66 · 특이도 0.92 | ⚠️ **보류** |
| **lofcz/ai-music-detector** | MIT | **3.59 KB** | 16 kHz | **ONNX Runtime** | 정확도 99.88% · FPR 0.31% | ❌ **기각** |
| lcrosvila/ai-music-detection | ⬜ 미확인 | CLAP 체크포인트 | ⬜ | CLAP | ⬜ | ⬜ 미조사 |

### ❌ `lofcz/ai-music-detector` 기각 — 이유 둘

용량 3.59 KB, MIT, 16 kHz 네이티브로 제약 적합성이 이례적으로 좋았으나 두 가지가 결정적이다.

1. **의존성**: 배포 형식이 `ai_music_detector.onnx` 이고 **`onnxruntime` 은 평가 서버 기본 설치
   목록에 없다.** 추가하면 "비어 있는 requirements.txt" 라는 안전마진을 잃는다.
   ⬜ 특징 추출 절차(FFT 크기·hop·3,585차원 구성)가 문서에 없어 numpy 재구현도 불가능하다.
2. **방법이 이 대회 데이터와 맞지 않는다.** 전치 컨볼루션이 만드는 **규칙적 스펙트럼 피크**
   (fakeprint)에 의존하는데, 문헌이 압축에 취약함을 명시한다 —
   *"압축은 높은 지각 품질을 유지하면서도 탐지 성능을 크게 저하시킨다. MP3 나 Encodec 으로
   8 kbps 까지 압축해도 탐지 모델의 정확도가 크게 떨어진다."*
   ([arXiv:2607.27454](https://arxiv.org/abs/2607.27454))
   **우리 평가셋은 MP3·FLAC 혼재에 전화채널까지 포함한다.** 정면으로 충돌한다.
3. 커버 범위도 `Suno ≤ 5`, `Udio ≤ 1.5` 로 한정된다. 다른 생성기에는 재학습이 필요하다.

> 99.88% 라는 수치에 끌리기 쉬우나 **자체 테스트 분할(in-domain)** 값이다.
> 우리 조건(손실압축·대역제한·미지 생성기)에서의 성능은 ⬜ 완전히 미검증이다.

### ⚠️ SONICS SpecTTTra 보류 — 기각은 아니다

- MIT · 17M · 16 kHz · 5초 윈도우로 제약 적합성은 양호하다
- 학습 데이터가 SONICS(97k곡 / 4,751시간, Suno·Udio 생성 49k) 로 **우리가 필요한 바로 그 분포**다
- 학습된 표현이라 스펙트럼 지문 방식보다 압축 내성이 나을 가능성이 있다 ⬜ 미검증
- **문제 1**: `pip install git+https://github.com/awsaf49/sonics.git` 가 필요하다.
  설치 10분 제한 안에 들어갈 가능성은 높지만 실패 시 설치 오류다(횟수 차감은 없다).
- **문제 2**: **F1 0.76 · 민감도 0.66** 은 강하지 않다. 5초 변형이라 문맥이 짧다.
  SONICS 논문의 상위 변형은 더 긴 문맥(최대 120초)을 쓴다 ⬜ 해당 체크포인트 공개 여부 미확인.
- **문제 3**: 과제 정의 불일치. SONICS 는 **곡 전체가 AI 생성인지**를 본다.
  우리는 **음악 성분이 AI 생성인지**를 묻는다. 보컬만 AI 인 혼합에서 오답 가능성이 있다.
- **문제 4**: 두 점수의 스케일이 달라 **융합식을 함께 재설계**해야 한다 (`02_model-design.md` 6절).

**결론: 지금은 넣지 않는다.** 기준선 점수가 없는 상태에서 새 모델·새 의존성·융합 재설계를
한꺼번에 바꾸면 무엇이 원인인지 알 수 없다. 기준선 확보 후 재평가한다.

## 4. 이번 회차에 실제로 바꾼 것

새 모델을 넣는 대신, **이미 가진 모델을 더 맞게 쓰는 쪽**을 택했다.

### `file_head` — `FILE_FAKE_PROB`(실효 가중치 0.45)를 원본에서 직접 얻는다

**문제**: 베이스라인은 FILE 을 `max(VP×VF, MP×MF)` 로 **합성**한다. 그런데
DF-Arena 는 ASVspoof 계열로 학습된 **파일 단위** spoof 탐지기다.
원본 전체를 그대로 넣는 것이 학습 설정과 정확히 일치한다.

현재 경로는 그 반대로 간다:

```
원본 16 kHz → 44.1 kHz 업샘플(도메인 밖) → Demucs 분리(아티팩트)
→ 스템 2개 채점 → 존재 확률 곱(순위 왜곡) → max
```

단계마다 원 분포에서 멀어진다. **가장 무거운 항목을 가장 간접적으로 구하고 있었다.**

**변경**: `CONFIG["file_head"]` 추가 — `fusion`(기본, 베이스라인 동일) · `direct` ·
`direct_max` · `direct_mean`

**비용**: 게이팅으로 분리를 건너뛴 파일은 원본이 곧 그 성분이라 **이미 계산돼 있다 → 추가 비용 0.**
혼합 파일만 DF-Arena 호출이 하나 는다. 67% 생략 가정 시 약 +19% 시간.

**권장 실험 순서**: `direct_max` 를 먼저 본다. 대회 정의가
"음성·음악 중 하나라도 FAKE 이면 파일 FAKE" 이므로 전체 증거와 성분 증거를 둘 다 살리는 쪽이 맞다.

### `segment_agg_voice` / `segment_agg_music` — 헤드별 집계 분리

음악 위조 단서는 곡 전체에 퍼지고 음성 위조 단서는 국소적일 수 있다.
실효 가중치 0.27 인 음악 헤드를 따로 조율할 수 있게 열어뒀다. 기본값은 `None`(전역값 사용).

### 검증

`scripts/selftest_logic.py` 에 26개 검사를 추가했다 — 네 가지 `file_head` 값의 수식,
게이팅 시 원본 재사용으로 **추가 호출이 발생하지 않음**, 집계 덮어쓰기 시 재사용 금지.
전체 통과.

## 5. 냉정한 평가 — 지금 가장 큰 제약

**아직 리더보드 점수가 하나도 없다.**

모델을 아무리 조사해도 우리 파이프라인의 실제 ADS 를 모르면 무엇을 고칠지 정할 수 없다.
자체 홀드아웃도 없다(학습 데이터 미제공 대회라 만들어야 한다).

→ **다음 행동은 모델 교체가 아니라 제출이다.** 기준선을 얻고,
`file_head` 를 한 칸 바꿔 0.45 항목의 반응을 본 뒤, 그 결과로 음악 헤드 투자 여부를 정한다.
