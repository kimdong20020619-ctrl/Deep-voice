# Codex 재검증 및 성능 개선 진행 순서

작성일: 2026-09-06. 내부 개발용 검토 기록이며 공모전 제출 보고서 본문이 아니다.

## 결론

현재 산출물은 실행 후보이지, 성능 개선이 검증된 최종 제출물이 아니다.
설정 스윕만으로 성능 상한을 정하지 않는다. 검증 품질을 확보한 다음 음악 판별 학습,
파일 판별 개선, 필요 시 다른 모델과의 앙상블을 비교한다. 최고점 달성이나 상승폭은 보장할 수 없다.

## 확인 범위와 결과

- 다운로드한 `Deepvoice.ipynb`: JSON 파싱 및 코드 셀 구문 검사 통과. 실행 출력은 없다.
- 현재 Git 변경: Kaggle 노트북과 생성기 수정, 붙여넣기용 코드 등이 존재. Codex는 이를 수정하지 않았다.
- `python -X utf8 -B scripts/selftest_logic.py`: 전체 통과.
- `python -X utf8 -B scripts/selftest_sweep.py`: 전체 통과.
- 위 테스트는 모델을 대체하는 스텁/합성 점수를 사용한다. 실제 모델 정확도나 GPU 완주 증거가 아니다.
- `python -X utf8 -B scripts/build_submit.py --check-only`: 통과. 시간 판정의 한계는 아래 참조.
- 로컬 모델 가중치는 `submit/model/SHA256SUMS.txt`의 각 항목과 모두 일치한다.
- `verify_bundle.zip` 전체 CRC 검사 통과. script.py, metric.py, sweep.py, build_valset.py는 로컬과 바이트 일치.
- `submit.zip` 루트는 model, script.py, requirements.txt이며 용량은 공식 제한 이내.
- `submit.zip`의 script.py는 현재 로컬과 일치. 큰 ZIP 전체 CRC 및 내부 모든 가중치 대조는 미실시.
- 로컬, 검증 번들, 제출 ZIP 모두 `file_head=direct`, `gate_music=0.10`이다.
- 첫 제출 기록은 `fusion`과 `gate_music=0.05`이므로 현재 ZIP을 첫 제출 보존본으로 취급하면 안 된다.
- Kaggle 실행 상태, 연결 데이터, 설치 패키지, 메모리, 실행 시간, 실제 검증 점수는 미검증.
- Kaggle에 업로드된 번들이 지금 로컬의 번들과 같은 버전인지는 미검증.

## 우선 해결할 문제

### 1. 음악 데이터 누락 시 총점 순위가 무효

`src/eval/metric.py:87`에서 Music EER의 NaN이 ADS와 Score로 전파된다.
가짜 음악 정답이 없는 입력으로 Score, ADS, Music EER 모두 NaN이 되는 것을 재현했다.
`src/eval/sweep.py:211`은 이를 차단하지 않고 정렬한다. `results[0]`은 유효한 우승 후보가 아니다.
대응: 진짜/가짜 음악을 확보하고, 지표가 정의되지 않는 경우 공식 총점 순위 선정을 중단한다.
부분 지표를 볼 수는 있지만 음악 항목을 임의로 채우거나 재가중한 값을 공식 총점으로 표시하지 않는다.

### 2. 폴더 이름만으로 만든 정답은 검증이 필요

노트북은 디렉터리명으로 real/fake, voice/music을 추론한다.
음악 파일에 보컬이 있으면 대회 정의상 혼합이다. 음악 폴더 전체를 음성 없음으로 라벨링하면 잘못된다.
출처 메타데이터와 표본 청취로 순수 반주 여부, 생성 여부를 확인한다.
중첩 real/fake 폴더의 중복 수집 여부도 검사한다. 실제 오분류 발생 여부는 현재 입력이 없어 미확인이다.

### 3. 검증셋에 반복 최적화하고 같은 데이터로 우승자를 고름

노트북은 같은 캐시에서 기본 스윕 후 추가 스윕을 한다. 독립 최종 확인셋이 없다.
합성 원본 경로도 labels.csv에 남기지 않아 원본 중복을 추적하기 어렵다.
대응: 합성 전에 원본 녹음/곡/화자/생성기 등의 그룹을 정의하고 개발용과 최종 확인용을 분리한다.
단순히 seed를 바꾸거나 합성 파일을 나누는 것만으로는 원본 중복을 막을 수 없다.
최종 확인셋에서 반복 튜닝하면 그것도 개발셋이 되므로 후보를 확정한 뒤 평가한다.

### 4. 실패한 파일이 검증에서 빠짐

`src/eval/sweep.py:94` 및 예외 처리 경로는 파일을 건너뛴다.
어려운 파일이 제외되면 점수가 실제 제출보다 좋아 보일 수 있다.
대응: 라벨 ID와 캐시 ID가 일치하는지 검사하고 누락 원인을 해결한다.
제출 경로의 폴백까지 평가할 때는 실패를 제외하지 않고 동일한 폴백 예측과 실패율을 함께 보고한다.

### 5. 빌드 통과는 실행 시간 보장이 아님

`scripts/build_submit.py:226`은 분리 생략률을 0.5로 가정하지만 이후 '시간 안전'이라고 출력한다.
실제 데이터에서 생략률이 다르면 추정이 달라진다. 특정 더미의 존재 점수는 전체 데이터의 잡음바닥이 아니다.
T4 측정과 L4 실행 사이에도 검증되지 않은 차이가 있다. 최고팀 CPS로 모델 구조나 평균 길이를 추론할 수 없다.
대응: 제출할 정확한 CONFIG에서 혼합/긴 파일을 포함한 처리 시간, 피크 메모리, 분리 비율을 측정한다.

### 6. 현재 노트북은 학습 및 다중 GPU 파이프라인이 아님

기존 가중치를 다운로드하고 예측을 캐시한다. 학습 루프가 없으며 임베딩도 수집하지 않는다.
DF-Arena와 Demucs는 기본 CUDA 장치를 사용하고 명시적인 두 GPU 작업 분할은 없다.
PANNs 등 외부 라이브러리 내부의 GPU 사용은 이번 검사에서 확인하지 않았으므로
'모든 라이브러리가 GPU 하나만 사용한다'고 단정하지 않는다. nvidia-smi 실측이 필요하다.
GPU를 두 개 선택했다고 VRAM이 하나로 합쳐지는 구조는 아니다.

### 7. 데이터 생성의 신호처리와 환경 준비

`src/synth/build_valset.py:69`는 선형 보간으로 리샘플한다. 실제 추론의 고품질 리샘플과 다르다.
저역통과 없는 다운샘플링은 위조 탐지의 단서를 변형할 수 있어 기존 오디오 라이브러리 경로와 비교해야 한다.
노트북에는 demucs, panns_inference 등 필요한 패키지의 설치/버전 점검 단계가 없다.
DACON 기본 설치 목록은 Kaggle 설치 상태의 증거가 아니다. Kaggle의 import 결과를 먼저 확인한다.
노트북의 고정 점수 차이를 '노이즈'로 보는 규칙도 실측 불확실성으로 검증되지 않았다.

## 실행 순서와 통과 조건

1. 현재 Kaggle 실행을 보존한다. 실행 중이면 무조건 Run All/재시작하지 않는다.
   번들 해제 셀은 작업 폴더를 삭제하고 다시 만든다. 현재 셀, 오류, 출력과 생성된 캐시 위치부터 확인한다.
   실행 결과가 있으면 노트북 출력, labels.csv, cache.pkl, 사용 CONFIG와 코드 해시를 보존한다.

2. 첫 제출 보존본과 현재 후보를 구분한다. 첫 ZIP이 없으면 당시 코드/설정/가중치를 찾아 복구 가능성을 확인한다.
   기록만 보고 '완전히 재현했다'고 선언하지 않는다. Claude와 Codex 후보는 서로 다른 작업 경로를 쓴다.

3. 데이터 소스를 확정한다. voice_real, voice_fake, music_real, music_fake 경로와 개수를 확인한다.
   각 출처의 라이선스와 보컬 여부를 확인하고 중복을 제거한다. 현재 라이선스 원장의 데이터 목록은 미완성이다.
   통과 조건: 출처와 정답 근거가 있고, 필요한 평가 항목에 양쪽 클래스가 모두 존재한다.

4. 검증 코드를 먼저 보완한다. NaN 순위 차단, 누락 ID 검사, 원본 출처 기록, 그룹 분리를 적용한다.
   현재 검토에서는 수정하지 않았다. 코드 변경은 별도 실행 단계로 진행한다.
   모델 비교 전 작은 공개 샘플로 합성 라벨과 오디오를 직접 확인한다.

5. Kaggle 환경을 점검한다. torch/torchaudio와 필요한 라이브러리 import, 가중치 해시를 확인한다.
   짧은 파일과 긴 혼합 파일로 디코딩부터 최종 확률까지 실행한다.
   통과 조건: 예외/메모리 부족 없음, 확률 유한 및 범위 정상, 실행 로그 보존.

6. 전체 개발셋 예측을 캐시한다. 중간 저장과 재개가 가능하도록 준비하고 누락 없이 완료됐는지 확인한다.
   세그먼트 구성, 패딩, 가중치, 전처리를 바꾸면 캐시를 다시 만든다.
   음악 프로브를 학습할 계획이면 별도의 학습 분할에서 임베딩을 수집한다. 기존 점수 캐시만으로는 학습할 수 없다.

7. 공통 기준선으로 설정 후보를 비교한다. 첫 제출 설정, 현재 direct 설정을 명시적으로 구분한다.
   현재 default_grid의 baseline(fusion)은 gate_music까지 되돌리지 않아 첫 제출 재현 설정이 아니다.
   File/Voice/Music EER, CPS, 유형별 오류, 처리 비용을 함께 기록한다.
   캐시 예측과 실제 추론을 동일 파일·설정으로 대조해 캐시의 충실도를 확인한다.

8. 성능 개선 후보를 만든다. Claude의 현재 설정 탐색과 별개로 Codex는 음악 판별 학습을 우선 검토한다.
   우선순위는 확인된 하위 지표로 조정한다. 음악이 실제 병목이라는 확정 증거는 아직 없다.
   임베딩 기반 선형 판별기를 낮은 비용의 출발점으로 평가하고 부족하면 부분 미세조정/다른 백본을 검토한다.
   원본·음성·반주 경로, 집계 방식, 파일 판별 결합을 비교한다. 새 의존성과 큰 학습 비용은 사전에 정리한다.
   한국어, 압축, 전화채널, 생성기 차이에 대한 일반화도 데이터가 확보된 범위에서 평가한다.

9. 각자 후보를 확정해 독립 확인셋과 제출 환경에서 확인한 뒤 제출한다.
   목표는 최종 총점이며 특정 하위 지표 개선만으로 채택하지 않는다.
   T4 두 개로 실험하더라도 제출은 L4 한 개 환경이므로 분산 실행에 의존하는 제출물을 만들지 않는다.
   인터넷 없이 실제 script.py가 완주하고 출력 ID·행·컬럼·유한값이 정상인지 확인한다.

10. 사용자 운영 방식대로 두 후보 점수를 비교하고 더 높은 후보에서 공동 보완한다.
    앙상블은 서로 다른 오류를 줄이고 시간/메모리 제한을 지킬 때만 채택한다.
    세 번째 제출은 보완 근거가 있는 후보로 진행한다. 다음 날은 마지막 후보와 기존 최고점을 비교해 시작한다.
    제출 ZIP, 코드, 가중치 해시, CONFIG, 검증 결과, 리더보드 결과를 연결해 보존한다. commit/push/제출은 사용자가 한다.

## 지금 필요한 입력

### 공식 배포물 추가 확인

바탕화면 `DEEPVOICE/open.zip`과 `[Baseline_Inference]_PANNs·HTDemucs·DF_Arena_1B 기반 AI 탐지.ipynb`를 읽었다.
ZIP에는 baseline_submit.zip, 제출 양식, 더미 WAV만 있다. 학습 정답은 없다.
세 WAV의 SHA-256이 동일하다. 모두 모노 PCM 16-bit, 16 kHz, 54,480 프레임으로 길이는 3.405초다.
따라서 세 파일은 독립적인 성능 표본이 아니며 실제 평가 길이/포맷/혼합 분포를 대표하지 않는다.
sample_submission.csv의 0.5는 제출 형식 예시이며 정답이 아니다.
공식 노트북은 zero-shot 방식이라고 명시한다. 현재 후보도 추가 학습 가중치가 활성화된 상태는 아니다.
공식 노트북의 Demucs 경로는 load_track으로 원본 채널을 읽는다.
현재 submit/script.py:261은 먼저 모노로 합치고, :435 부근에서 채널을 복제해 Demucs에 넣는다.
스테레오의 공간 정보가 사라지므로 공식 경로와 수학적으로 동일하다는 주장은 성립하지 않는다.
실제 성능 저하가 확인된 것은 아니며, 공식 채널 보존 경로와 현재 경로를 같은 스테레오 파일에서 비교해야 한다.
현재 확장자 지원 확대와 예외 폴백은 실행 안정성 변경이며 정확도 향상을 증명하지 않는다.
공식 노트북과 압축 내부 script.py는 줄바꿈 정규화 후에도 완전히 일치하지 않는다.
확인된 차이는 main의 인자 처리다: 노트북은 parse_arguments([]), ZIP은 parse_arguments()이다.
이는 노트북 실행을 위한 차이로 볼 수 있으며 성능 차이의 증거는 아니다. 전체 차이 목록은 별도로 추출하지 않았다.
공식 ZIP 내부 SHA256SUMS.txt의 세 해시는 앞서 로컬 가중치와 대조한 목록과 동일하다.

- Kaggle 소스 수집 출력: 네 종류의 개수와 연결된 데이터 이름.
- 현재 실행 중인 셀, 오류 또는 최종 결과. 다운로드본에는 출력이 없다.
- cache.pkl과 labels.csv가 생성됐는지 여부.
- 첫 제출 ZIP 보존 여부 및 오늘 추가 제출 여부.

- 제출 추론은 파일별 독립성을 유지해야 한다. 배치 처리를 하더라도 배치 내 다른 파일의 값으로
  정규화·순위화·보정하지 않는다. 한 파일 내부 세그먼트 집계만 허용된다.
- 2차 평가 대상이 되면 재현 가능한 학습 코드, 모델 개발 보고서(HWP), 학습데이터 구성 보고서(HWP),
  학습 데이터 일체와 팀 구성원 정보를 기한 내 제출해야 한다. 따라서 외부 데이터 원본·생성 스크립트·
  라이선스·해시·학습 설정을 지금부터 보존한다.
- 자원 사용 조건은 개별 원문 검증이 필요하다. 이 문서는 전체 라이선스 감사 완료를 의미하지 않는다.
- 원격 Kaggle 실측이 없으므로 전체 실행 검증 완료 또는 점수 개선 완료가 아니다.
- 사용: web 도구(공식 원문 확인), PowerShell/Python(읽기·재현·기존 검사). 별도 스킬은 적용하지 않았다.
- 이번 AI 활용 내역은 공모전 AI 활용 기록 파일에 당일 기록할 것.
