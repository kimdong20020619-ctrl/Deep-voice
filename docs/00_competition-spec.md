## 과제 ✅

오디오 1개당 5개 확률 예측.

| 컬럼명 (확정) | 의미 | 담당 헤드 |
|---|---|---|
| `FILE_FAKE_PROB` | 파일 전체가 FAKE일 확률 | 결합 |
| `VOICE_FAKE_PROB` | 음성 성분이 FAKE일 확률 | Head B |
| `MUSIC_FAKE_PROB` | 음악 성분이 FAKE일 확률 | Head C |
| `VOICE_PRESENT_PROB` | 음성이 존재할 확률 | Head A |
| `MUSIC_PRESENT_PROB` | 음악이 존재할 확률 | Head A |

CSV 컬럼 순서는 `ID` + 위 5개. 소수 10자리, UTF-8.

### 오디오 유형 정의 ✅

| 유형 | 정의 |
|---|---|
| 음성 | 사람의 발화 또는 **보컬**만 포함 |
| 음악 | **보컬이 없는** 반주·악기음만 포함 |
| 혼합 | 음성과 음악이 동시에 또는 **순차적으로** 포함 |

> **보컬은 음성 성분이다.** 따라서 보컬+반주 노래는 **혼합**이다.
> "순차적으로"도 혼합에 포함된다 — 앞부분은 음악, 뒷부분은 음성인 파일도 혼합이다.
> → 세그먼트 집계에서 max를 쓰는 베이스라인 방식이 순차 혼합에는 유리하지만, 존재 확률과
>   FAKE 확률을 같은 방식으로 집계해도 되는지는 검증이 필요하다.

### Real(0) / Fake(1) 기준 ✅

- AI로 **생성된** 음성·음악 성분 → FAKE
- AI로 생성되지 않은 실제 원천 → REAL
- **음성·음악 중 하나라도 FAKE이면 파일 전체가 FAKE**
- 품질 개선·잡음 제거·음량 조정 등 **성분 자체를 새로 생성하지 않는 후처리만 적용된 경우 REAL**

> 마지막 항이 중요하다. 증강으로 만든 학습 데이터에서 **REAL에 강한 후처리를 걸어도 REAL 라벨을
> 유지해야 한다.** 오히려 그런 샘플을 일부러 넣어야 모델이 "후처리 아티팩트 = FAKE"로 학습하는
> 지름길(shortcut)을 막을 수 있다.

## 데이터 ✅

**학습 데이터는 제공되지 않는다. 참가자가 직접 구성한다.**

배포되는 `open.zip` 구조:

```
open.zip
├─ baseline_submit.zip        # 베이스라인 코드 및 모델이 포함된 제출 파일 (참고용)
└─ data/
    ├─ test/
    │   ├─ TEST_0000.wav      # 형식 확인용 더미 3개
    │   ├─ TEST_0001.wav
    │   └─ TEST_0002.wav
    └─ sample_submission.csv  # 3행 × 6컬럼 (ID + 5개 예측값)
```

평가 데이터 (외부 비공개):

- 총 **1,200개** 오디오 파일
- 채널: **모노/스테레오 혼재** (샘플별로 다름)
- 길이 **4초 ~ 1분**, 샘플레이트 16 kHz
- 형식 **MP3 · WAV · FLAC 등 혼재** (배포 더미는 WAV뿐 — 여기서 사고가 난다)
- **일부 전화채널 포함**
- 음성 / 음악 / **혼합** 오디오 등 다양한 유형
- 평가 시 `data/test/`가 동일 경로·구조로 실제 데이터로 교체되어 제출 zip이 실행된다
- 출력은 1,200행, `sample_submission.csv`와 동일한 컬럼 구조

## ⬜ 미확인 — P1 착수 전 반드시 채운다

### 1. 평가 지표 ✅ 가중치 확정 / ⬜ 정의 미확인

리더보드 1위 실측값: 총점 **0.83984** / ADS **0.82323** / CPS **0.98932**

```
0.9 × 0.82323 + 0.1 × 0.98932 = 0.839839 ≈ 0.83984
```

→ **총점 = 0.9 × ADS + 0.1 × CPS** ✅ (산술 정확 일치)

ADS·CPS의 정의는 ⬜ 미확인. 상세는 `05_baseline-analysis.md` 2절.
**어느 해석이든 결론은 같다 — 점수의 90%가 ADS이고 CPS는 이미 포화다.**

남은 확인 사항:
- [ ] ADS·CPS의 정확한 명칭과 계산식 (AUC인가 EER인가, 컬럼별 가중치는)
- [ ] Public / Private 분할 비율
- [ ] 결측·범위 이탈 값의 처리

### 2. 평가 서버 실행 환경 ✅ 확정

### 3. 제출 형식 ✅ 확정

컬럼명·순서·정렬 규칙은 베이스라인 코드로 확정됐다 (`05_baseline-analysis.md` 1절).
`sample_submission.csv`의 ID 순서를 그대로 따라야 하며, 오디오 파일은 stem 기준으로 매칭한다.

### 4. 라벨 정의 ✅ 대부분 해소

위 「Real/Fake 기준」으로 해소됐다. 남은 것:

- [ ] 음성이 없는 파일의 `VOICE_FAKE_PROB`은 0인가, 채점에서 제외되는가
      (베이스라인은 무음 RMS 게이트로 0.0을 낸다 → 0이 맞을 가능성이 높지만 미확인)
