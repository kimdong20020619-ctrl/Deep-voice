# 파일 판별 프로브 학습 — 2026-09-15

## 목적과 판단

이전 음악 파일럿에서는 direct/max 대비 집계 변경의 개선이 없었다. 다음 단계는 DF-Arena의 기존 특징에 작은 L2 로지스틱 회귀를 학습해 판별 표현의 활용 가능성을 검증하는 것이다. 전체 백본을 미세조정하지 않는다. 이 문서는 내부 실험 기록이며 대회 제출 보고서 본문이 아니다.

**전체 대회 성능 평가가 아닌 음악 파일 중심의 FILE 판별 학습 가능성 확인 실험이다.** 성분 정답이 없어 Voice/Music EER, CPS, 대회 총점은 산출하지 않는다. 음악 파일을 썼다는 이유로 FILE 결과를 Music EER이라고 부르지 않는다. 얻은 가중치를 제출에 자동 반영하지 않는다.

## 데이터 설계

공식 MUSAN 스트림 https://openslr.trmal.net/resources/17/musan.tar.gz 에서 FMA 음악을 제한적으로 수집한다. FakeMusicCaps 공식 배포 https://zenodo.org/records/15063698 는 Range 접근으로 선택 파일만 수집한다. MUSAN의 연주자·라이선스 근거는 기존 고정 리비전 메타데이터와 대응한다. 데이터셋 설명은 https://www.openslr.org/17/ 및 2015년 원 논문 https://arxiv.org/html/1510.08484, FakeMusicCaps 라이선스는 CC BY-NC 4.0이다.

실제 음악은 이전 파일럿 연주자 Airglow, Alecs_Band, Arne_Huseby를 모두 제외했다. 연주자당 최대 두 곡으로 제한한다. 생성 음악은 이전 파일럿 설명 ID와 초기 조사 표본 설명 ID를 제외했다. 과거에 본 표본 자체를 최종 확인 자료로 쓰지 않는다.

연주자 그룹은 고정 난수 순서로 학습/개발/확인에 배정했다. 생성 음악은 설명 ID 해시 분할과 생성기 배정을 모두 만족하는 파일만 선택했다. train은 MusicGen_medium/musicldm/mustango, development는 audioldm2, holdout은 stable_audio_open이다. 이 생성기들은 과거 파일럿에서 일부 출력이 노출됐으므로 완전히 처음 접한 생성기라고 주장하지 않는다. 새 학습의 생성기와 최종 확인 생성기를 분리한다는 의미다.

다운로드와 계획 기록의 원음 86개 중 Morgan_Sadler의 두 곡은 개별 LICENSE의 Attribution-NoDerivatives 조건 때문에 크롭·학습 배포 번들에서 제외했다. 원본 조사 기록은 남기고 번들 manifest에 제외 ID를 기록한다. 선택된 곡의 개별 출처·제목·연주자·라이선스 파일과 변경 내역을 번들에 보존한다.

완성 번들의 실제 구성은 학습 52개(실제 25/생성 27), 개발 16개(각 8), 확인 16개(각 8), 총 84개다. 번들 manifest와 생성기 출력으로 집계 확인했다. 이 숫자는 충분한 최종 검증 규모라는 의미가 아니다. 특히 확인셋은 실제 연주자 4그룹과 생성기 1종뿐이다.

모든 파일은 원본 중앙 8초, peak 0.95로 정규화, mono 16kHz PCM16이다. 실제/생성 모두 같은 함수를 사용한다. 전체 길이/채널/코덱 분포를 재현하지 않는다. 원본 파형 해시·크롭 해시·그룹·생성기 중복이 분할을 넘으면 중단한다. 해시가 다른 재녹음·리마스터·실제 곡 유사성까지 검증한 것은 아니다.

## 학습과 선택

1. 번들·모델 해시 확인 후 DF-Arena를 한 번 로드한다. PANNs와 Demucs 실행 없이 원본 오디오 특징만 추출한다.
2. 파일별 특징을 NPZ로 저장한다. 누락·비유한값을 거부하고 오디오 해시 및 코드/모델 목록/환경이 맞는 캐시만 재사용한다.
3. train 세그먼트로만 표준화 평균/표준편차와 로지스틱 회귀를 학습한다. 개발/확인 특징을 표준화 통계에 포함하지 않는다.
4. C=0.001, 0.01, 0.1을 미리 고정했다. 개발 File EER, AUC, 작은 C 순으로 선택한다. 파일 점수는 세그먼트 확률 max다. 수렴 경고는 실패로 처리한다.
5. 선택한 프로브와 DF-Arena 원본/max 기준을 확인셋에서 한 번 비교한다. 확인 결과 파일이 이미 있으면 재실행을 거부한다. 확인 결과를 본 뒤 다른 하이퍼파라미터로 재튜닝하면 새 확인셋이 필요하다.
6. 저장한 가중치의 계산을 제출 코드 LinearProbe와 수치 대조한다. 이것은 전체 제출 파이프라인 완주·총점 검증을 대체하지 않는다.

현재 특징 차원에 비해 표본 수가 적어 과적합 위험이 크다. 좋은 확인 결과도 다음 확장 실험의 근거일 뿐, 즉시 최종 제출 모델로 채택할 근거가 아니다. 나쁜 결과라면 정규화 계수만 무한 탐색하지 말고 오류·데이터 규모·특징 적합성을 재평가한다.

## 실패·검증 기록

생성 음악 수집 중 DNS 오류가 발생했다. 완료 항목을 파일별 해시로 확인한 뒤 남은 항목만 재개했다. 부분 수집 상태는 최종 manifest 생성과 구분한다. 전체 원본 아카이브의 체크섬은 검증하지 않았다.

일부 float WAV의 진폭이 1을 넘어 기존 PCM 변환 검사가 중단됐다. 해당 파일을 몰래 잘라내거나 제외하지 않고, 전체 실험 음원에 같은 peak 정규화를 적용했다. 먼저 받은 파일까지 원본에서 다시 처리해 번들에 넣는다. 따라서 최종 크롭 해시는 원본 수집 폴더의 과거 test 파일보다 **번들 manifest**가 기준이다. 음량 정규화로 이전 파일럿과 입력 조건이 달라졌으므로 이전 EER와 직접 비교하지 않고 새 데이터에서 기준 모델도 함께 평가한다.

로컬 검사는 분할 누수·클래스 누락 거부, 모의 특징을 이용한 실제 sklearn 학습/선택/평가, 저장된 프로브와 제출 LinearProbe 계산 일치, 확인셋 재평가 거부를 포함한다. 최초 테스트는 가짜 torch 객체에 SciPy가 확인하는 Tensor 속성이 없어 실패했고 테스트 대역을 수정했다. 모의 특징에서의 높은 점수는 실제 모델 성능이 아니다.

실제 GPU 특징 추출·학습·확인 점수는 사용자 Colab 실행 전에는 미검증이다. 네트워크·메모리·라이브러리 호환성 오류가 없다고 보장하지 않는다. 신규 라이브러리 추가 없이 기존 사용 패키지를 재사용한다.
