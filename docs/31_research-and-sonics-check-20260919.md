# 관련 자료 재조사와 다음 실험 — 2026-09-19

## 결론

다음 실행은 **공개 음악 탐지 모델 SONICS의 고정 가중치 검증**으로 정했다. 기존 DF-Arena 임베딩 위에 작은 선형 판별기를 더 학습하는 경로는 우선 중단한다. 지난 외부 검증에서 그 판별기들이 안정적으로 개선되지 않았기 때문이다. 새 모델의 실제 점수 향상은 아직 미검증이다.

이 문서는 내부 조사·개발 기록이며 공모전 제출 보고서 본문이 아니다. 인터넷의 모든 관련 자료를 완전하게 조사했다는 뜻은 아니다. 대회 공식 원문, 후보의 저자 논문, 공개 코드·가중치·라이선스와 현재 로컬 실험을 우선 조사했다.

## 논문에서 가져온 판단과 가져오지 않은 결론

[SONICS 논문](https://arxiv.org/html/2408.14080v3)은 긴 음악 문맥을 사용하는 모델과 Suno/Udio 노래 데이터셋을 제시한다. 하지만 120초 성능을 4~60초 대회 입력에 그대로 기대할 수는 없다. 그래서 5초 모델을 주 비교로 두고 120초 모델은 기존 60초 방송 음원에서 공식 패딩 방식으로만 진단한다.

[AI-Generated Music Detection and its Challenges](https://arxiv.org/abs/2501.10111)는 데이터의 장르·압축 같은 혼동 요인과 일반화 문제를 다룬다. 이번에도 원본 점수만 보고 채택하지 않고 같은 음원의 MP3 변형을 함께 평가한다. 단일 64 kbps MP3 검사가 모든 코덱·전화 환경을 대표하지는 않는다.

[Improved Robustness in AI-Generated Music Detection](https://arxiv.org/html/2607.27454v2)은 주파수 스케일 변화에 대한 구조적 대응을 제시한다. 이 논문이 있다는 이유로 모든 스펙트럼 방식이 압축에 실패하거나 모든 신경망 방식이 강건하다고 단정하지 않는다. 압축 내성은 실제로 확인한다.

[BUT ASVspoof 연구](https://arxiv.org/abs/2408.11152)의 결과를 근거로 현재 DF-Arena 백본이 대회에서 최적이라고 확정할 수 없다. 과제·학습·평가 환경이 다르므로 기존 문서의 ‘백본 선택이 독립 검증되어 교체 논의를 종결한다’는 식의 강한 판단은 이번 의사결정에 사용하지 않는다.

기존 09번 조사에서 SONICS 긴 문맥 가중치는 공개 여부 미확인 상태였다. 이번에는 공식 모델 페이지와 고정 리비전 메타데이터로 공개를 확인했다. 기본 설치 목록에 없는 패키지가 필요하다는 사실만으로 모델을 기각하는 판단도 채택하지 않는다. 설치 가능성·시간·성능을 구분한다.

## 로컬 제출본 대조

`data/research/sonics-20260919/baseline_inventory.json`에 로컬 제출 ZIP 6개의 크기, 코드 SHA-256, CONFIG, 모델 항목 크기·CRC 및 현재 코드와의 AST 차이를 기록했다. 기존 ZIP은 수정하지 않았다. 전체 ZIP/대형 가중치를 이번에 다시 해시 검증한 것은 아니다.

- 로컬 `submit.zip` 내부 코드 SHA-256: `8ef622e27358932d570b212a4bab8df3be7af5059f8155624a8ce68620ff38bc`
- 현재 `submit/script.py` SHA-256: `26192e78f94d5bf86eb90b4aeb1711f1c8ddd92499348991bf771a1898d119d6`
- `file_head=direct`, `segment_agg=max`, 음악 상수 헤드 미사용이라는 설정은 이전 최고점 기록과 부합한다.
- 현재 코드에는 프로브·직접 처리 경로 등이 추가됐고 처리 함수가 변경돼 있다. DF-ArenaScorer 클래스의 AST는 같다.
- 서버에 제출된 원본 ZIP 해시는 없으므로 로컬 `submit.zip`이 제출 ID 83676의 정확한 원본이라는 연결은 여전히 미검증이다. 이번 스크리닝의 기준 예측은 확인된 외부 실험 결과이며 리더보드 기준선의 완전 재현이 아니다.

## 확정한 실험 설계

원본 128개를 사용한다. 기존 개발 음악 비교 대상 48개, 음성 및 가짜 음성 혼합 대조군 32개, AI-OpenBMAT 외부 음원 48개다. 각 집단을 별도 보고하며 중복 원천에서 만든 혼합 파일을 독립 원본으로 세어 통계적 유의성을 주장하지 않는다.

1. 모든 입력을 16 kHz 모노로 읽는다. 원본 파일 해시·라벨·이전 결과 대응을 확인한다.
2. 원본과 64 kbps MP3 재인코딩/디코딩본을 만든다. 재생성한 오디오 해시와 길이를 남긴다. 새 라벨이나 학습은 없다.
3. alpha-5s는 5초 구간을 전부 처리한다. 끝부분이 남으면 마지막 완전 구간을 포함하며 짧으면 오른쪽 0 패딩한다. 각 구간을 공식 평가 로더와 같은 표준편차 방식으로 정규화한다. **확률 평균이 사전 지정 주 지표**이며 max는 진단용으로만 같이 기록한다.
4. alpha-120s는 외부 60초 음원에만 적용하고, 공식 평가 로더와 같이 오른쪽을 120초까지 0 패딩한 뒤 정규화한다. 짧은 입력을 긴 입력으로 보이게 늘이는 위험이 있어 이 결과를 주 후보 선택에 쓰지 않는다.
5. 합계 352개 모델·조건별 예측을 저장한다. 구간별 로짓, 시작 위치, 파일별 점수, 코드, 환경, 모델 버전 및 출처를 결과 ZIP에 남긴다.
6. 원본에 한해서 기존 DF-Arena 예측과 EER/AUC를 비교한다. MP3 변형의 DF-Arena는 이번에 재추론하지 않으므로 MP3에서의 모델 간 우열은 주장하지 않는다.

이 데이터는 이미 여러 번 본 개발 데이터이며 새로운 잠금 검증셋이 아니다. SONICS가 학습한 생성기에 Suno가 포함되므로 AI-OpenBMAT를 SONICS의 ‘미지 생성기’ 테스트라고 부르지 않는다. 가중치 학습 음원과 완전 중복 여부도 미검증이다.

음악 점수와 파일 점수는 같은 개념이 아니다. 파일 EER를 보고하는 이번 실험은 후보 스크리닝이다. 음성/음악 성분 점수, 존재 점수 및 대회 총점은 산출하지 않는다. 음악 비교 집단 두 곳에서 주 후보의 EER/AUC가 일관되게 개선되고 압축 후 심각한 붕괴가 없어야 다음 통합 검증을 검토한다. 통과해도 자동 제출하거나 즉시 최고점 모델을 교체하지 않는다. 별도 원본 검증과 음성 성능 보존, 오프라인 전체 파이프라인 확인이 남는다.

- torchvision 등 기존 Colab 의존성이 맞지 않으면 숨기지 않고 중단한다. `fvcore`는 성능 프로파일 전용 코드에서만 필요하며 이 실행 경로에서는 설치하지 않는다.
