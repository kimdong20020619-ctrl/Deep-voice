# 혼합 학습 결과: 제출 채택 보류

## 판단

혼합 학습 probe를 기존 제출 모델의 대체로 채택하지 않는다. 개발 자료 전체를 합친 File EER는 개선됐지만 음악 단독과 음성이 큰 혼합의 성능이 이전 음악 전용 probe보다 악화됐다. 음악 혼합 문제를 해결했다고 볼 수 없다. 기존 제출 코드·가중치·ZIP은 변경하지 않았다.

이번 선택 기록의 C=0.1은 새 학습 후보 세 개 중 최선이라는 뜻이다. 이전 모델까지 포함한 최선이라는 뜻은 아니다. 조건별 평균과 전체 합산 EER는 다른 통계이며, 조건별 평균은 대회 Score가 아니다.

## 동일 개발 입력 비교

수치는 File EER이며 낮을수록 좋다. 수치 순서는 **DF-Arena 기준 / 이전 음악 probe / 새 혼합 probe**다.

이전 LibriSpeech 8화자 혼합 실험과 이번 LJSpeech 혼합 실험은 입력과 클래스 구성이 다르다. 음성이 큰 혼합에서 이전 음악 probe가 이번에는 상대적으로 좋다고 해서 지난 실험의 실패가 사라진 것은 아니다.

## 실패 조건 추가 분석

혼합 그룹의 실제+실제 음성/음악 8개를 공통 음성 대조군으로 두고, 가짜 성분별 양성 8개를 각각 비교했다. 이는 파일 단위 진위의 부분집합 분석이며 Voice EER/Music EER가 아니다. 부분집합들은 공통 대조군을 공유하므로 독립 실험으로 세지 않는다.

- 새 혼합 probe의 실제 음성+생성 음악 File EER는 -6 dB와 +6 dB 모두 0.5였다.
- 새 혼합 probe의 생성 음성+실제 음악 File EER는 두 조건 모두 0.25였다.
- 따라서 음성이 작은 전체 혼합의 개선만 보고 생성 음악 탐지도 개선됐다고 해석하면 안 된다. 이번 개선은 생성 음성 쪽 부분집합에서 나타났다.
- 데이터 다양성 부족, 입력 전체 특징에서의 성분 간 간섭 등을 원인 후보로 볼 수 있지만 이번 실험만으로 원인을 확정할 수 없다.

## 검증한 내용

`python -X utf8 -B scripts/audit_mixed_probe_results.py`가 성공했다.

- 반환 ZIP CRC·중복 경로, 배포 매니페스트 및 실행 코드·학습 코드·이전 가중치·원본 모델 해시 목록의 바이트 일치 확인.
- 348개 특징 파일 및 해시 연결, 학습 268개와 개발 80개 분리, 원본 그룹·해시·생성기 분리 확인. 학습 세그먼트는 536개다.
- 학습 특징만으로 평균/표준편차를 재계산하여 저장된 새 판별기의 표준화 값과 정확히 일치함을 확인.
- 반환 가중치와 특징으로 개발 예측을 재계산. CSV와 최대 절대 차이 5.551115123125783e-17.
- CSV와 재구성한 점수에서 EER/AUC를 다시 계산하여 summary.json과 모두 일치함을 확인.
- 기록된 후보 지표에 사전 선택 규칙을 적용했을 때 C=0.1이 선택되는 것을 확인. 미선택 후보를 로컬에서 별도 재학습하지는 않았다.
- 실제 GPU 특징 추출은 Tesla T4, torch 2.11.0+cu128에서 완료된 결과다. 공식 평가 서버 환경이나 전체 제출 추론 검증을 대체하지 않는다.
- 반환 ZIP에는 원본 대형 모델 가중치 자체가 없으므로 실제 실행 가중치를 독립 재해시하지는 못했다. 배포·노트북 해시 검사와 실행 기록을 근거로 구분한다.

## 다음 진행 방향

동일한 작은 개발 자료에서 C나 혼합 비율을 계속 조정하지 않는다. 다음 실험은 이미 있는 혼합 음원을 사용해 **분리 전 원본과 분리된 음악 신호에서의 판별 차이**를 확인하는 방향이다. 분리 과정이 생성 흔적을 훼손할 수도 있으므로 개선으로 전제하지 않는다. 의미 있는 후보가 나오면 새 화자·음악 원본·생성기의 미사용 자료로 검증하고, 그 후 전체 오프라인 추론·시간 제한을 확인한다. 현재 결과만으로 대회 점수 향상을 예상하거나 제출 횟수를 사용하지 않는다.
