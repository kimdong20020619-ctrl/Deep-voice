# 08. 대회 규정 준수 점검

> 데이콘 「부정 제출 및 치팅 행위」 공지 및 대회 규칙 기준 자체 점검.
> 2026-09-05 작성. 코드가 바뀔 때마다 갱신한다.

공지의 요지 — 수상 후보군은 **소스 코드를 직접 제출**해야 하고, 대회 명세 준수 여부·
분석 절차의 문제 유무·**분석 절차의 완결성**을 평가받는다.
부정 행위자뿐 아니라 **미완결 코드 제출자도 실격**이다.

따라서 이 레포는 처음부터 "제3자가 읽고 재현하고 검증할 수 있는 상태"를 목표로 한다.

---

## 1. 부정 제출 — 해당 없음

| 공지 항목 | 우리 상태 |
|---|---|
| 인간이 예측한 값 제출 | 없음. 모든 값은 `submit/script.py` 실행 결과다 |
| 검색 등을 통한 수기 작성 | 없음 |
| 형평성에 어긋나는 참가 방식 | 없음. 개인 1계정, 중복 등록 없음 |
| 평가 데이터셋 유출 시도 | 없음. `data/` 는 읽기 전용으로만 접근한다 |

### 폴백값 0.5 에 대하여

디코딩 실패 파일에 중립값 0.5 를 넣는다. 이것이 "인간이 예측한 값"에 해당하는지 짚어둔다.

- **아니다.** 특정 파일의 정답을 추정해 손으로 적은 값이 아니라, **예외 처리의 기본값**이다.
  AUC·EER 모두에서 0.5 는 정보량이 0인 중립값이라 유리하게 작용하지 않는다.
- `script.py` 는 실패 건수와 실패 ID, 전체 트레이스백을 **표준출력에 남긴다.** 숨기지 않는다.
- 실패가 다수 발생하면 그것은 고쳐야 할 버그이지 감출 대상이 아니다.
  실행 로그에서 `실패 N건` 을 반드시 확인하고 `docs/04_experiment-log.md` 에 기록한다.

## 2. 추론 규정 — 파일 단위 독립 예측

> 규칙: "다른 파일 샘플의 정보·예측값·통계 등을 활용하여 예측값을 생성하거나 보정하는 방식은
> 허용되지 않습니다." / "하나의 파일 샘플을 세그먼트 단위로 분할하여 추론하고, 결과를 종합하는
> 방식은 허용됩니다."

**EER 은 순위 기반 지표라 테스트셋 전체 분포로 점수를 정규화하는 트릭이 매우 유혹적이다.
이것이 정확히 금지 대상이다.** 실수로도 넣지 않도록 두 겹으로 막았다.

| 방어 | 위치 |
|---|---|
| 설계 원칙 명시 | `script.py` 최상단 docstring |
| 집계는 파일 내부에서만 | `aggregate_segment_scores()` — 한 파일의 세그먼트만 입력받는다 |
| 루프 구조 | `main()` 이 파일 하나씩 처리하고 파일 간 상태를 공유하지 않는다 |
| 자동 검사 | `scripts/build_submit.py` 가 `rankdata`·`StandardScaler`·`quantile_transform`·`zscore` 를 발견하면 **빌드 실패** 처리 |

향후 코드를 수정할 때도 이 검사를 통과해야 zip 이 생성된다.

### 비공개 평가 데이터를 이용한 학습 — 없음

`script.py` 에 학습·튜닝·Pseudo-Labeling 코드가 없다. 추론만 한다.
`torch.inference_mode()` 안에서만 모델을 호출하고 옵티마이저·손실함수를 import 하지 않는다.

## 3. DF-Arena `forward` 배치 패치 — 규정 검토

`script.py` 의 `install_batch_patch()` 는 벤더 모델의 `forward` 를 런타임에 교체한다.
검토가 필요한 부분이므로 근거를 남긴다.

**무엇을 바꾸는가**

```python
# 벤더 원본 (model/df_arena_1b/backbone.py)
def forward(self, x):
    out_ssl = self.ssl_model(x.unsqueeze(0))
    ...

# 패치본 — 이 한 줄만 조건부로 바꾸고 나머지 연산은 동일하다
def forward(self, x):
    if x.dim() == 1:
        x = x.unsqueeze(0)
    out_ssl = self.ssl_model(x)
    ...
```

원본은 입력 차원과 무관하게 `unsqueeze(0)` 하므로 `(B, T)` 배치를 넘기면 `(1, B, T)` 가 되어
Wav2Vec2 가 동작하지 않는다. 패치는 **1개 세그먼트를 넣을 때 원본과 완전히 동일**하고,
여러 세그먼트를 한 번에 넣을 수 있게만 한다.

**왜 규정 위반이 아닌가**

- 대회 규칙: "제출하는 추론 코드에서는 예측을 위한 전처리·후처리 및 추론 과정은
  **자유롭게 구성할 수 있습니다**." 이는 추론 과정 구성에 해당한다.
- **모델 가중치를 바꾸지 않는다.** 학습도 튜닝도 아니다.
- **수학적으로 동등하다.** 배치 차원이 독립인 구조다 —
  `BatchNorm2d` 는 `eval()` 모드라 running statistics 를 쓰고,
  attention pooling 의 softmax 는 시간축(`dim=1`)에 걸려 샘플 간에 섞이지 않는다.
- **런타임에 실제로 검증한다.** `DFArenaScorer._probe()` 가 같은 입력 3개를
  단일 경로와 배치 경로로 각각 통과시켜 최대 편차를 측정하고,
  허용치를 넘으면 **배치를 끄고 원본과 같은 단일 경로로 되돌린다.**
  편차 수치는 실행 로그에 남는다.
- 벤더 파일 `model/df_arena_1b/backbone.py` 는 **배포본 그대로 두었다.**
  심사자가 원본과 패치를 나란히 대조할 수 있다.

목적은 속도뿐이고 점수 의미는 바뀌지 않는다. 끄려면 `CONFIG["batch_patch"] = False` 로 둔다.

## 4. 재현성 — 2차 평가 대비

> 제출물: "Private Score 재현이 가능한 학습 코드"

현 단계는 zero-shot 이라 재현 대상이 추론뿐이다. 학습이 들어가면 아래를 지킨다.

- [ ] 난수 시드를 코드에 고정하고 값을 문서에 기록
- [ ] 학습 데이터 생성 스크립트를 커밋 (합성 파이프라인은 시드로 재생성 가능해야 한다)
- [ ] 체크포인트와 그것을 만든 커밋 해시를 `docs/04_experiment-log.md` 에 함께 기록
- [ ] 제출한 zip 과 레포 상태를 1:1로 대응시킨다 (어떤 커밋이 어떤 제출인지)
- [ ] 클린 환경(새 Kaggle 노트북)에서 학습 → 제출 전 과정을 한 번 재현

**「학습에 활용한 데이터 파일 일체 포함」** 이 제출 조건이므로, 데이터 규모를 처음부터
제출 가능한 크기로 설계한다. 대용량 공개 데이터셋 전체가 아니라
**실제 학습에 쓴 서브셋 + 재생성 스크립트** 형태로 간다. → `docs/01_data-design.md`

## 6. 솔직하게 짚어둘 것 — AI 코딩 도구 사용

이 레포의 코드는 AI 코딩 도구(Claude Code)의 도움으로 작성되고 있다.
데이콘 공지는 "인간이 예측한 값 제출"과 "형평성에 어긋나는 참가 방식"을 금지하며,
**코딩 도구 사용 자체를 금지하지 않는다.** 규칙도 "사용에 법적 제한이 없는 모든 방법론 가능"이다.

다만 실질적인 위험이 하나 있다.

**수상 후보에 오르면 소스 코드를 직접 제출하고 심사자에게 설명해야 한다.**
"분석 절차의 완결성"이 평가 항목이고, 미완결 코드 제출자는 실격이다.
따라서 참가자 본인이 다음을 설명할 수 있어야 한다.

- 왜 3개 헤드로 나눴는가, 각 헤드가 어떤 지표에 얼마나 기여하는가
- 융합식을 왜 그렇게 골랐는가 (실험 근거는 `04_experiment-log.md`)
- 학습 데이터를 어떤 원칙으로 구성했는가 (`01_data-design.md`)
- 배치 패치가 왜 결과를 바꾸지 않는가 (3절)

이 문서들은 그 설명을 위한 재료다. **읽지 않고 제출하면 그 자리에서 무너진다.**
보고서 2종을 본인이 직접 쓰는 것이 이 위험에 대한 가장 확실한 대비다.
