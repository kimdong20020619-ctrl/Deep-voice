## 결론

기존 코드에는 후보 순위를 잘못 해석하게 만드는 결함이 있다. 작성 도구와 관계없이 실제 경로와 회귀 검사로 판단했다. 이번 수정은 성능 측정의 신뢰성을 높이는 작업이며 점수 상승 증거가 아니다. 기존 최고점 ZIP 및 제출 추론 코드는 변경하지 않았다.

## 수정한 내용

| 위치 | 문제 | 조치 |
|---|---|---|
| src/eval/metric.py / rank_score | Music EER이 없을 때 부분 점수로 순위를 정함 | 공식 총점이 유한하지 않으면 순위 선정을 중단. 부분 지표 출력은 진단용으로 유지 |
| src/eval/sweep.py / build_truth, sweep | 누락·중복 ID를 허용해 일부 파일만 평가할 수 있음 | 정답과 캐시의 ID 집합·유일성·비어 있음 검사. 0/1이 아닌 정답 거부 |
| src/eval/sweep.py / predict | 전달된 프로브가 설정을 끈 기준선에도 적용될 수 있음 | 후보 CONFIG에 따라 프로브를 전달. 활성 후보에 모델이 없으면 중단. 실패 시 CONFIG 복구 |
| src/synth/build_valset.py / load_16k_mono | 선형 보간 다운샘플링에 고역 접힘 방지 필터가 없음 | 이미 사용 중인 SciPy의 resample_poly로 변경 |
| src/synth/build_valset.py / build | 가짜 음악이 없어도 생성 진행, 원본 추적 정보 누락 | 네 종류 원본 필수, 생성 수·클래스 확인, voice_source/music_source 기록 |
| scripts/make_valset_notebook.py 및 생성 산출물 | 부분 점수·캐시 일치에 대한 과도한 설명 | 새 동작에 맞게 안내 수정 및 노트북·붙여넣기 코드 재생성 |

누락 캐시가 있으면 전체 labels.csv를 그대로 전달해야 한다. 호출자가 정답도 함께 잘라 누락을 숨기는 것은 이 검사만으로 탐지할 수 없다. precompute 자체의 실패 후 재개·체크포인트 저장은 이번에 구현하지 않았다.

## 재현 검사

저장소 루트에서 실행:

```powershell
python -X utf8 -B scripts/selftest_validation_guards.py
python -X utf8 -B scripts/selftest_sweep.py
```

- 새 회귀 검사 12개 통과. 부분 점수 순위 차단, 누락·중복·추가 ID, 정답 재정렬, 잘못된 정답, 프로브 비활성·활성 전달, 모델 누락 시 복원, 소스 부족, 고역 접힘 억제, 원본 경로 기록을 검사했다.
- 기존 스윕 자체 검사 통과. 출력 점수는 인공 데이터로 만든 테스트 결과이며 실제 대회 성능이 아니다.
- Python 구문, 노트북 JSON, 셸 매직 줄을 제외한 코드 셀 구문 검사 통과. 셸 명령과 GPU 셀은 실행하지 않았다.
- git diff --check 통과. Git 줄바꿈 경고는 있었으나 공백 오류는 없었다.
- 로컬 soundfile이 없어 첫 새 테스트 실행이 실패했다. 오디오 I/O를 대체한 검사로 범위를 명확히 했고, 기존 torch 스텁의 Tensor 타입 누락도 수정한 후 통과했다. 실제 오디오 디코딩·저장 검사는 미실시다. 새 패키지는 설치하지 않았다.

## 다음 성능 실험

1. 실제 원본 음성·음악 데이터 및 사용 조건을 확보한다. 현재 로컬 data에는 공식 더미만 있고, 과거 검증 캐시는 발견되지 않았다.
2. 원본 곡·녹음·화자 및 생성기 그룹을 먼저 정의하고 학습/개발/최종 확인 분할을 나눈다. 합성 파일 ID만 나누면 같은 원본이 양쪽에 들어갈 수 있다. 이번 원본 경로 기록은 추적 기반이지 자동 누수 방지 완료가 아니다.
3. 같은 입력과 설정에서 최고점 ZIP의 추론 경로와 캐시 예측을 대조한다. 리샘플링 변경 후 새로 합성한 데이터는 과거 캐시를 재사용하지 않는다.
4. 음성 경로를 고정한 상태에서 FILE·MUSIC 판별 후보를 비교한다. 단순 설정 후보와 임베딩 프로브를 비교하되, 프로브는 별도 학습 분할에서 적합한다. 부분 위조 파일의 모든 세그먼트에 파일 라벨을 일괄 복제하는 학습도 점검 대상이다.
5. 독립 확인셋 성능과 실제 GPU 비용이 확인된 후보만 제출한다. 하루 제출 3회는 소진 목표가 아니다.

기존 verify_bundle.zip과 제출 ZIP은 변경하지 않았다. 원격 실행을 시작할 때는 이번 src 변경을 포함하는 새 검증 번들을 만들고, 번들·설정·데이터 목록·출력·시간을 함께 보존해야 한다.
